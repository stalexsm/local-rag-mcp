# ADR-0001: Тулчейн — uv, ruff, ty

## Статус

Принято (2026-08-30). Контекст — спека «миграция на uv + ruff + ty» (GitHub issue #1).

## Контекст

Проект собирался вручную: зависимости перечислялись в `requirements.txt` с
«плавающими» версиями `>=` без лока, виртуальное окружение каждый создавал
сам по инструкции (`python3 -m venv venv` + `pip install`), а соглашения о
качестве кода (стиль, типы) не поддерживались ни одним инструментом. Каждый
разработчик и каждый агент собирал окружение заново и спорил о стиле в ревью.

Требования к тулчейну: воспроизводимое окружение одной командой, единственный
источник зависимостей, детерминированные проверки стиля и типов, минимум
изменений рантайма (проект остаётся «запуск из `src/`», не пакет).

## Решение

- **uv** — менеджер окружения и зависимостей, режим non-package: манифест
  `pyproject.toml` в корне, пин Python 3.12 (`.python-version`), лок
  `uv.lock` в git, `requirements.txt` удалён. Dev-инструменты — группой
  `dependency-groups.dev`.
- **ruff** — линтер (дефолт E4/E7/E9/F + isort, pyupgrade, bugbear, simplify,
  `line-length = 100`) и форматтер. Официальные pre-commit-хуки ruff-check и
  ruff-format ставят стиль заслоном на каждый коммит.
- **ty** — проверка типов в ratchet-режиме: базлайн «0 диагностик» на
  `uv run ty check src`; любые новые диагностики — регрессия. Запускается
  локальной командой, в pre-commit сознательно не включён (быстрые коммиты).

## Трейдоффы

### uv против pip + requirements.txt

- **pip**: лока нет — `pip freeze` вручную и неизбежно расползается; окружение
  и интерпретатор ставятся отдельными шагами; резолвер медленный. Для агентов
  это означало «собери окружение по инструкции и надейся».
- **uv**: `uv sync` из лока воспроизводит окружение; сам скачивает Python 3.12
  при отсутствии; один манифест вместо синхронизации двух файлов.
- **Минусы uv**: молодой, быстро развивающийся инструмент — ломающие изменения
  CLI возможны; требует установки uv на машину (Homebrew или standalone-
  скрипт). Смягчение: поверхность CLI стабильна для базовых команд, пин
  `uv.lock` гарантирует воспроизводимость независимо от версии uv.

### uv против poetry

- **poetry** — полноценный менеджер проектов: подталкивает к пакетной
  структуре, сборке и установке самого проекта. Наш код — не пакет и пакетом
  становиться не должен (соглашение «запуск из `src/`», относительные пути в
  `config.py`); non-package режим у poetry не первоклассный.
- **uv** в режиме `package = false` закрывает ровно нужное: окружение, лок,
  запуск. Реструктуризация в устанавливаемый пакет — отдельное будущее
  решение, сейчас оно out of scope.

### ty против mypy

- **mypy** — зрелый стандарт: стабилен, огромная экосистема плагинов и
  заглушек. Минусы для этого проекта: медленный, шумный на дефолтах,
  требует заметной настройки до полезного сигнала.
- **ty** — очень быстрый, осмысленные дефолты без конфигурации, понятные
  сообщения. Дешёвые находки (аннотации сигнатур) были починены сразу,
  игноры не понадобились.
- **Минусы ty**: preview-статус — между версиями возможны ломающие изменения
  и новые классы диагностик. Смягчение: версия заперта в `uv.lock`, обновление
  — осознанный шаг с пересмотром базлайна; стратегия ratchet (порог только
  ужесточается: фикс или точечное обоснованное игнорирование, без глобальных
  отключений правил).

### Принятие preview-статуса ty

Принимается осознанно: скорость и качество сигнала «здесь и сейчас» важнее
гарантий стабильности, которые для кодовой базы такого размера даёт mypy.
Риск локализован пином в локе — базлайн «0 диагностик» не может поплыть
сам по себе, только вместе с явным обновлением зависимости.

## Последствия

- Окружение: `uv sync` (из корня) — единственный шаг установки.
- Запуск: из `src/` — `uv run python main.py [build-index]`; `uv run`
  находит манифест в корне, соглашение о путях сохранено.
- Проверки (из корня): `uv run ruff check .`, `uv run ruff format --check .`,
  `uv run ty check src`; на каждый коммит — pre-commit-хуки ruff.
  Инструкции и траблшутинг: `src/COMMANDS.md`, раздел «Development Checks».
- При обновлении ruff в `uv.lock` синхронно обновляется `rev` в
  `.pre-commit-config.yaml`, чтобы хук и локальные команды совпадали.
- Рантайм-поведение не изменилось: контрольный проход «пересборка индекса +
  smoke-запрос» после миграции воспроизводит прежний результат.
