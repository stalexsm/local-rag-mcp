# ADR-0002: Полнотекстовый поиск — rank_bm25 в памяти, без нового артефакта

## Статус

Принято (2026-08-30). Контекст — спека «Hybrid Search (FTS) и Query Expansion» (Task-RAG.txt).

## Контекст

Спека требует полнотекстовый поиск параллельно с векторным. Варианты: SQLite FTS5
(дисковый артефакт рядом с `index.faiss`/`chunks.pkl`) и `rank_bm25` (индекс в памяти).
Корпус мал — десятки документов, сотни чанков, — поэтому токенизация всего корпуса
занимает миллисекунды.

## Решение

`rank_bm25` в памяти: BM25-индекс строится из уже загруженного `chunks.pkl` при
инициализации, третьего артефакта на диске нет. Рассинхронизация индекса с чанками
невозможна по построению; `build-index` остаётся единственной командой пересборки.

SQLite FTS5 отклонён: второй дисковый артефакт добавил бы обязанность синхронной
пересборки в `build_index.py` и риск рассинхрона без выгоды на корпусе такого размера.
Цена решения — новая зависимость `rank_bm25` (чистый Python, без транзитивных зависимостей).
